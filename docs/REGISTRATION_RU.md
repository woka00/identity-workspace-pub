# Регистрация с подтверждением почты через Brevo

Регистрация открыта всем после включения `REGISTRATION_ENABLED=true`. По умолчанию она выключена, чтобы обновление кода без настроенного почтового сервиса не открывало неработающую форму. Старые аккаунты продолжают входить по логину и паролю.

## Сценарий

1. На экране входа пользователь нажимает «Создать аккаунт» и указывает почту.
2. Backend отправляет через Brevo одноразовую ссылку со сроком действия 30 минут. Аккаунт ещё не создаётся, пароль ещё не запрашивается.
3. По ссылке пользователь выбирает логин и пароль (15–128 символов). Подтверждение почты, создание обычного аккаунта и его пустого профиля выполняются одной транзакцией.
4. Пользователь входит с новым логином и паролем. Вход также работает в desktop-приложении, даже если ссылка была открыта в обычном браузере.

Проверка уникальности логина не расходует ссылку: при занятом логине можно выбрать другой. Новое письмо отменяет предыдущую ссылку. Обновление страницы после открытия письма удалит токен из памяти — откройте ссылку из письма снова. Автоматический просмотр ссылки почтовым сканером не подтверждает регистрацию: требуется явная отправка формы.

## Хранение и защита

- Пароли: существующий PBKDF2-HMAC-SHA256, 600 000 итераций, случайная соль 16 байт. Открытый пароль не сохраняется и не отправляется Brevo.
- Токен: 32 случайных байта; в PostgreSQL только SHA-256. Одноразовое потребление и проверка срока защищены блокировкой строки и транзакцией, включая параллельные запросы.
- Почта: AES-256-GCM со случайным nonce и привязкой к аккаунту. Уникальность проверяется по HMAC-SHA256, ключ которого отдельно выводится из `DATA_ENCRYPTION_KEY`. Нет открытого email-столбца и нет обычного перебираемого SHA-256 адреса. Без ключа запись почты запрещена даже в development.
- Логин остаётся обычным отображаемым идентификатором, как и раньше. Содержимое задач и профилей этим изменением не переводится в зашифрованное хранилище. Хеширование необратимо и не подходит для данных, которые нужно затем показать пользователю.
- Ссылка строится только из настроенного HTTPS `PUBLIC_URL`, а не из входящего Host. Токен находится во фрагменте `#register=…`, удаляется из адресной строки и держится только в памяти формы. Не используется localStorage/sessionStorage. GET не выполняет регистрацию; POST защищён существующими same-origin/CSRF-проверками.
- Brevo вызывается с сервера по HTTPS, с таймаутом 10 секунд, без переходов по редиректам и без вывода тела ответа провайдера в логи/HTTP-ошибки. Ключ API отсутствует во frontend/desktop-сборке.
- Запрос письма не раскрывает, зарегистрирован ли адрес. Для существующего адреса также отправляется ссылка; сообщение о существующем аккаунте доступно только обладателю токена из письма.
- Email и ссылка неизбежно передаются Brevo для доставки. Это защита хранения в нашей БД, а не сквозное шифрование электронной почты. В запросе передаётся `contactPixelTrackingConsent=false`; включите обработку согласия на уровне аккаунта Brevo, отключите tracking для этих писем и сократите срок хранения транзакционных логов в настройках сервиса.

## Ограничения отправки

В PostgreSQL действуют общие для всех реплик лимиты: одно письмо на адрес в минуту, максимум 5 на адрес в час, 100 отправок в час и 500 за 24 часа суммарно. Неудачные попытки обращения к Brevo тоже расходуют лимит. По умолчанию эти пределы могут превышать квоту вашего тарифа Brevo; при необходимости уменьшите константы `Registration*Limit` в `backend/internal/application/registration.go`.

На HTTP-уровне дополнительно допускаются 8 запросов с IP и 30 суммарно за 15 минут отдельно для запроса письма и завершения регистрации на процесс сервера. Ограничены параллельные обращения к Brevo и вычисления хешей. История отправок старше суток и просроченные заявки очищаются при следующем запросе регистрации. Постоянные аккаунты не удаляются. Для большого публичного запуска дополнительно настройте лимиты reverse proxy и наблюдение за квотой: встроенные ограничения могут временно закрыть регистрацию при распределённой атаке.

## Настройка на сервере

1. Настройте и подтвердите отправителя/домен в Brevo. Нужен **API key**, не SMTP key. Официальная инструкция: [отправка транзакционных писем](https://developers.brevo.com/docs/send-a-transactional-email).
2. Сохраните ключ в `secrets/brevo_api_key` с правами `600`, каталог `secrets` — `700`. Не помещайте ключ в Git, чат, frontend или аргументы команд. Откройте файл локальным редактором. Существующий `DATA_ENCRYPTION_KEY` сохраните: не заменяйте его новым ключом.
3. В серверном `.env` задайте `REGISTRATION_ENABLED=true`, `BREVO_SENDER_EMAIL` (подтверждённый адрес) и при желании `BREVO_SENDER_NAME`. `PUBLIC_URL` должен указывать на реальный HTTPS-адрес приложения с действительным сертификатом. Для адреса по IP особенно важно проверить, что ссылка из письма открывается в обычном браузере без ошибки сертификата.
4. К production Compose добавьте `-f docker-compose.registration.yml` **после** `-f docker-compose.prod.yml`. Этот overlay монтирует `secrets/brevo_api_key` и передаёт `BREVO_API_KEY_FILE`. Используйте один и тот же набор файлов для build, migrate и up.
5. Сделайте и проверьте backup по [production-инструкции](../PRODUCTION_DEPLOYMENT_RU.md), соберите образ, примените новую миграцию `045_email_registration.sql` штатной командой `run --rm app migrate`, затем обновите `app`. Не включайте автоматические миграции как обход штатного процесса. Локальные изменения сами по себе ничего не меняют на сервере.

Пример команды проверки конфигурации, без вывода значений секретов:

```sh
docker compose -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.registration.yml config --quiet
```

Без Docker backend также поддерживает `BREVO_API_KEY_FILE`. Включение регистрации без ключа Brevo, отправителя, ключа шифрования или HTTPS-адреса приводит к отказу запуска. Отключение — `REGISTRATION_ENABLED=false` и перезапуск backend; существующие аккаунты сохраняются.

После выкладки проверьте доставку реального письма, создание аккаунта, вход в браузере и desktop, повторную/просроченную ссылку и новую отправку. Автоматические тесты используют имитацию Brevo, не подтверждают доставляемость и настройки вашего домена.
