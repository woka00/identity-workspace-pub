# identity workspace для компьютера

Electron-оболочка открывает существующий веб-сайт в отдельном окне на Linux, macOS и Windows. Go-сервер и PostgreSQL продолжают работать на сервере: устанавливать их на компьютер пользователя не нужно. Обновления сайта становятся доступны при перезагрузке окна; изменения самой оболочки требуют новой сборки.

## Адрес workspace

Публичная сборка по умолчанию открывает `http://localhost:8080`. Для подключения к другому развёрнутому серверу передайте точный HTTPS-origin без пути и параметров:

```bash
IDENTITY_WORKSPACE_URL=https://workspace.example.com npm start
```

Та же переменная может быть задана в среде запуска установленного клиента. Валидатор принимает только HTTPS-origin; HTTP разрешён лишь для `localhost`/loopback-адресов. Публичный исходник не содержит production-адресов.

Верхнее меню и системная строка заголовка удалены: сайт занимает всё окно. В правом верхнем углу поверх интерфейса находятся компактные кнопки свернуть, развернуть/восстановить и закрыть, без отдельной плашки. В Linux сверху зарезервирована светлая полоса высотой 40 px: содержимое сайта начинается под ней, поэтому кнопки не перекрывают интерфейс. Перетаскивание работает по всей свободной верхней области, кроме трёх кнопок.

Для каждой ОС нужен свой файл:

| Система | Файл из `desktop/dist/` | Действия пользователя |
| --- | --- | --- |
| Ubuntu / Debian / Linux Mint, x64 | `identity-workspace-0.2.3-linux-amd64.deb` | Открыть в системном установщике пакетов, нажать «Установить», подтвердить системным паролем. Запустить из списка приложений. |
| Windows, x64 | `identity-workspace-0.2.3-win-x64.exe` | Открыть мастер установки, выбрать папку и завершить установку. Создаются ярлыки на рабочем столе и в меню «Пуск». |
| macOS, Apple Silicon / Intel | `identity-workspace-0.2.3-mac-arm64.dmg` / `identity-workspace-0.2.3-mac-x64.dmg` | Открыть DMG, перенести приложение в Applications и запустить. |

Передавайте сам установщик, а не каталог `linux-unpacked` или исходники. Один универсальный установщик для всех ОС не создаётся. Если в Linux нет графического обработчика `.deb`, пакет можно установить из каталога загрузки командой `sudo apt install ./identity-workspace-0.2.3-linux-amd64.deb`.

`.deb` содержит ярлык, установочные скрипты electron-builder и профиль AppArmor для установленного приложения. Они настраивают sandbox при установке; ручной `chmod` из инструкции для разработки пользователю пакета не предназначен. Для установки системных зависимостей может понадобиться интернет. Дополнительный AppImage — переносная версия, которая не заменяет установку `.deb`; FUSE и ограничения sandbox зависят от дистрибутива.

## Запуск из исходников

Нужен Node.js 22.12+ (рекомендуется 24 LTS).

```bash
cd desktop
npm ci
npm start
```

Адрес сервера берётся из `IDENTITY_WORKSPACE_URL`, а при её отсутствии используется `http://localhost:8080`. Проверка HTTPS-сертификатов остаётся включённой.

Без меню работают сочетания Ctrl+C/V/X/A/Z, Ctrl+Shift+Z, Ctrl+R (перезагрузка), Ctrl+W (закрыть окно), Ctrl+Q (выход). На macOS вместо Ctrl используется Cmd. На Linux и Windows закрытие последнего окна завершает приложение; на macOS для завершения используйте Cmd+Q.

Браузерные данные остаются в постоянной сессии `persist:workspace` в стандартной папке Electron `userData`. Сессия входа отделена от обычного браузера. Сохранение входа между запусками зависит от срока и атрибутов cookie, установленных сервером. Для выхода из аккаунта используйте кнопку выхода внутри сайта.

### Linux: ошибка SUID sandbox helper

Если `npm start` завершается с `The SUID sandbox helper binary was found, but is not configured correctly`, проверьте файл установленного Electron. Для SUID sandbox он должен принадлежать `root` и иметь режим `4755`. Из папки `desktop/`:

```bash
sudo chown root:root node_modules/electron/dist/chrome-sandbox &&
sudo chmod 4755 node_modules/electron/dist/chrome-sandbox
stat -c '%U %G %a %n' node_modules/electron/dist/chrome-sandbox
npm start
```

Ожидаемые владелец, группа и режим: `root root 4755`. Команды относятся только к helper-бинарнику; само приложение запускайте обычным пользователем. После переустановки или обновления Electron права могут сброситься. На файловой системе с `nosuid` такой способ не работает: потребуется установка в подходящее расположение или настройка AppArmor для user namespaces конкретного приложения. Не отключайте sandbox или ограничения AppArmor глобально.

Справка: [настройка SUID helper Chromium](https://chromium.googlesource.com/chromium/src/+/main/docs/linux/suid_sandbox_development.md), [ограничения user namespaces в Ubuntu](https://documentation.ubuntu.com/security/security-features/privilege-restriction/apparmor/).

## Сборка

```bash
npm run check
npm run pack        # каталог приложения для текущей ОС, без установщика
npm run dist:linux  # DEB + AppImage
npm run dist:mac    # DMG + ZIP
npm run dist:win    # NSIS EXE
```

Результаты находятся в `desktop/dist/`. По умолчанию используется архитектура компьютера сборки. Например, на macOS `npm run dist:mac -- --arm64` собирает Apple Silicon, а `--x64` — Intel.

Если Electron уже скачан через `npm start`, для повторной локальной Linux-сборки можно использовать его без повторной загрузки:

```bash
npm run dist:linux -- --x64 --config.electronDist=node_modules/electron/dist
```

### Сборка всех ОС в GitHub Actions

Добавлен workflow [`desktop-installers.yml`](../.github/workflows/desktop-installers.yml). После размещения изменений в GitHub запустите **Actions → Desktop installers → Run workflow**. Он собирает Linux x64, Windows x64, macOS arm64 и macOS x64 на соответствующих runner-ах. Скачайте результат нужной ОС из **Artifacts**, распакуйте архив и передайте пользователю установщик из него. Артефакты хранятся 14 дней. Workflow запускается вручную и не публикует GitHub Release.

Собирайте и проверяйте каждую платформу на соответствующей ОС; macOS-сборка и Apple signing требуют macOS. Команды не публикуют артефакты автоматически. Для Linux AppImage может потребоваться FUSE; альтернативный запуск — `./identity-workspace-….AppImage --appimage-extract-and-run`. Не отключайте Chromium sandbox флагом `--no-sandbox`; ограничения sandbox нужно решать на уровне поддерживаемой конфигурации ОС.

Это начальная сборочная конфигурация. Сертификаты Windows, подпись и notarization macOS не настроены; перед публичным распространением настройте их через возможности electron-builder и проверьте установку на чистых системах. Автоматического обновления оболочки пока нет. Перед каждым выпуском обновляйте Electron до актуального поддерживаемого патча и повторяйте проверки.

## Границы первой версии

- Сайт работает в sandbox, без Node.js и без preload/IPC-доступа к компьютеру. Три кнопки окна работают в отдельном локальном WebContentsView с собственной сессией. Только его основной frame может отправлять команды свернуть, развернуть и закрыть. Локальный view закрывается вместе с окном.
- Переходы внутри сайта и на точный OAuth-origin `https://authentication.fatsecret.com` остаются в окне и используют одну браузерную сессию. Другие HTTPS-ссылки открываются в браузере после подтверждения. Дополнительные OAuth-переходы, в том числе вход через сторонних провайдеров, нужно проверять отдельно; при необходимости подключения интеграций через обычный браузер они сохраняются в аккаунте на сервере.
- Камера и уведомления требуют отдельного разрешения для текущего сайта. Микрофон и остальные разрешения запрещены. Выбор файла с фото и обычные загрузки файлов используют браузерные механизмы.
- Web Push/PWA и напоминания после закрытия приложения не считаются поддержанными этой оболочкой. Нативные фоновые уведомления потребуют отдельной реализации.
- Офлайн-хранилище и локальный сервер не добавлены. При недоступном сервере приложение предлагает повторить подключение или закрыть окно.

## Будущие виджеты Linux

Для компактных окон с таймером, задачами и трекерами можно добавить отдельные `BrowserWindow`, использующие сессию `persist:workspace`, и специальные компактные представления сайта. Это позволит сохранить авторизацию и серверные данные. Настройки позиции и размера относятся к desktop-слою; бизнес-правила таймера и задач остаются в существующих слоях приложения.

Окно приложения и нативный виджет рабочего стола — разные механизмы. Для KDE Plasma понадобится отдельный plasmoid, для GNOME Shell — расширение. Возможности размещения окна, закрепления и поведения поверх других окон также зависят от Wayland/X11 и оконного менеджера. Эти интеграции в первую версию не входят.

## Проверка перед выпуском

После `npm run check` проверьте на каждой целевой ОС: автоматическое открытие заданного сервера; отсутствие меню и работу сочетаний клавиш; вход/выход; задачи и таймер; повторный запуск; недоступность сервера и повтор подключения; OAuth FatSecret; экспорт PDF; выбор фото и камеру; внешние ссылки; установку и удаление пакета. Проверки URL в `test/` не заменяют эти сценарии.

Документация: [безопасность Electron](https://www.electronjs.org/docs/latest/tutorial/security), [форматы пакетов](https://www.electron.build/docs/targets/), [сборка для разных ОС](https://www.electron.build/docs/features/multi-platform-build/).
